# UI/UX Design Review

Use when asked to critique a website, landing page, dashboard, prototype, or app screen.

## Review framework
Evaluate:
- User goal and clarity of the primary action
- Information architecture and navigation
- Visual hierarchy, typography, spacing, and alignment
- Consistency of components and design tokens
- Mobile and tablet behavior
- Accessibility: contrast, labels, keyboard access, focus, and target sizes
- Content quality, trust signals, and error prevention
- Performance and perceived speed
- Conversion friction and unnecessary steps

## Process
1. Identify the target audience and main user task. If unknown, state assumptions.
2. Separate critical usability issues from polish opportunities.
3. For each finding, describe the observed issue, why it matters, and a concrete fix.
4. Prioritize by impact and effort: P0 critical, P1 high, P2 medium, P3 low.
5. Avoid vague advice such as “make it modern” or “improve spacing.” Specify what to change and where.
6. Do not invent observations about screens or behavior you have not seen. Ask for screenshots, files, or a URL when needed.
7. If asked to implement fixes, preserve established brand choices and existing product behavior unless a change is necessary.

## Output format
Start with a short overall assessment, then a prioritized table with columns: Priority, Finding, Impact, Recommended fix. End with the highest-value next steps.
